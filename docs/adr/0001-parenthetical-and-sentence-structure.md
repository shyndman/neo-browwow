# Represent sentences and parentheticals as endpoint-tagged text spans

Academic prose embeds citations and asides inside round parentheses `(...)` and square brackets `[...]` that frequently cross inline formatting (`emphasis`, `strong`, `link`) and contain internal sentence breaks. Downstream stages need to classify and conditionally omit parentheticals from speech generation while highlighting spoken fragments in the reading view at `Text`-leaf granularity.

Instead of inserting custom `Sentence` and `Parenthetical` parent nodes into the Markdown AST — which forces cleaving inline formatting wrappers across boundaries and creates awkward nesting when multi-sentence parentheticals sit inside or alongside host sentences — we keep the tree as standard mdast, split only `Text` leaves at bracket and sentence boundaries, and represent `Sentence` and `Parenthetical` as flat `TextSpan` records (`{ commonAncestor, start, end, text }`) attached via split-aware `TextMetadata` exclusively on their `start` and `end` `Text` leaves:

- **Standard mdast without ancestor cleaving**: Because only `Text` leaves are split in place within their immediate parent's `children`, inline formatting (`emphasis`, `strong`, `link`) remains intact for the reading view and standard Remark/Rehype tooling.
- **Single-leaf fast path and bounded walks**: Retaining `(` / `)` and `[` / `]` on the parenthetical's boundary `Text` leaves keeps unstyled parentheticals as a single `Text` leaf (`start === end`), allowing consumers to read `start.value` directly without walking the tree; when `start !== end`, `commonAncestor` bounds any subtree traversal to the tightest enclosing mdast `Parent`.
- **Split-aware endpoint migration**: Attaching `TextMetadata` (`starts` and `ends`) only to boundary `Text` leaves keeps interior leaves and non-text inline nodes (`inlineMath`, `inlineCode`, `image`) metadata-free. When a boundary `Text` leaf is split into `[left, right]`, `onSplit` migrates `starts` to `left` and `ends` to `right` while `commonAncestor` stays unchanged.
- **Strict bracket balancing**: Plain text leaves within each paragraph balance `(...)` and `[...]` strictly on a single stack (including empty and whitespace-only pairs) and fail parsing on crossed, unclosed, or unmatched brackets, relying on upstream LLM extraction to emit math, inline code, and enumeration markers as structured Markdown.
- **Host and standalone sentence spans**: Inline `Parenthetical` spans remain inside one intact host `Sentence` span so omitting a `Parenthetical` leaves a complete `Sentence`; an inline `Parenthetical` emits inner `Sentence` spans only when internal sentence boundaries split it into multiple sentences. Standalone `Parenthetical` spans (where the top-level sentence slice contains only optional whitespace outside `Parenthetical`) emit their `Sentence` span(s) inside the `Parenthetical` without a redundant outer `Sentence`.
